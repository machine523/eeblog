# 💻↔️💻 在多台电脑上管理博客

> 核心思路：**GitHub 仓库是博客的"中央大脑"**。
> 文章、样式、配置全在仓库里；任何一台电脑都只是仓库的一个副本，
> 改完 push 回去，其他地方 pull 一下就同步了。
>
> 你的仓库地址：**<https://github.com/machine523/eeblog>**
> 所有文章都在仓库的 **`src/content/posts/`** 文件夹里，每篇是一个 `.md` 文件。

---

## 三种写作方式（按轻便程度排序）

### 方式 1：GitHub 网页直接编辑（最轻，任何设备都行，连 iPad 都可以）⭐

1. 浏览器打开 <https://github.com/machine523/eeblog> 并登录
2. 进入 `src/content/posts/` 文件夹
3. **改文章**：点某篇 md → 右上角铅笔图标 ✏️ 直接改
4. **新文章**：右上角 **Add file → Create new file**，文件名填
   `src/content/posts/my-new-note.md`（注意要带上文件夹路径），
   从现有文章复制开头那段 `---` 包起来的信息区（标题/日期/标签/图标），
   改一改，下面写正文
5. 拉到底部点 **Commit changes**（提交说明随便写，比如"新增学习笔记"）

保存后 GitHub 自动重新构建，**几分钟后 https://eebolg.online 就更新了**——
全程不需要装任何软件，这是"在另一台电脑管理博客"最省事的答案。

### 方式 2：另一台电脑用 VSCode 写（体验最好，有本地预览）⭐

适合经常写、想边写边看效果的情况。在**那台电脑**上做一次性准备：

**第一步：装两个软件（只装一次）**

1. 安装 **Git**：<https://git-scm.com/download/win> 下载，一路下一步
2. 安装 **VSCode**：<https://code.visualstudio.com> 下载，一路下一步
3. （想要本地预览才需要）安装 **Node.js LTS**：<https://nodejs.org> 下载，一路下一步

**第二步：把博客克隆到本地硬盘（只做一次）**

打开 VSCode，按 `` Ctrl+` ``（左上角波浪号键）打开终端，执行：

```bash
# 先进入一个你想放博客的目录，比如 D 盘
cd /d D:\

# 克隆仓库（会在 D:\ 下生成 eeblog 文件夹，这就是你博客的本地副本）
git clone https://github.com/machine523/eeblog.git

cd eeblog
```

第一次 push 时 VSCode 会弹出 GitHub 登录窗口，用浏览器授权一次以后就记住了。

**第三步（可选）：本地预览**

```bash
npm install      # 只在克隆后第一次需要，约 1-3 分钟
npm run dev      # 启动后浏览器打开 http://localhost:3000 边写边看
```

**以后每次写作（VSCode 图形化操作，不用记命令）：**

1. 打开 VSCode → 文件 → 打开文件夹 → 选 `D:\eeblog`
2. 终端里先执行 `git pull`（把网页上/其他电脑上的最新改动拉下来）
3. 在左侧文件树 `src/content/posts/` 里写/改 md 文章
4. 点左侧第三个图标（源代码管理）→ 在输入框写提交说明（如"新增 FPGA 笔记"）
5. 点 **✓ 提交** → 再点 **同步更改**（或"推送"）
6. 等几分钟，网站自动更新

### 方式 3：本机（你现在这台）继续写

流程完全一样，只是别忘了：**开始写之前先 `git pull`**，
因为另一台电脑（或 GitHub 网页）上的修改要先拉回本地，否则 push 时会被拒绝。

## Git 常用命令速查（就这几句够用）

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `git pull` | 把 GitHub 上的最新内容拉到本机 | **每次开始写作前** |
| `git status` | 看看改了哪些文件 | 提交前检查 |
| `git add .` | 把所有改动装进"待提交包" | 写完文章后 |
| `git commit -m "说明"` | 给这次改动拍个快照并命名 | add 之后 |
| `git push` | 把快照上传到 GitHub | commit 之后 |
| `git log --oneline` | 查看历史快照 | 想看看以前改了啥 |

## 冲突了怎么办（很少见）

如果同一篇文章在两边都改了，push 时 Git 会提示冲突。
小白最简单的处理：先把冲突的 md 文件复制一份备份，然后

```bash
git checkout -- 冲突的文件名
git pull
```

再把备份里自己写的内容手动合并回去。愿意学原理的话搜「git 冲突解决」。

## ⏰ 一个提醒

`node_modules/`（依赖）和 `dist/`（构建产物）**不需要也不会**同步到 GitHub——
它们已经在 `.gitignore` 里被排除了。每台电脑克隆后自己 `npm install` 一次即可。

# 💻↔️💻 在多台电脑上管理博客

> 核心思路：**GitHub 仓库是博客的"中央大脑"**。
> 文章、样式、配置全在仓库里；任何一台电脑都只是仓库的一个副本，
> 改完 push 回去，其他地方 pull 一下就同步了。

---

## 三种写作方式（按轻便程度排序）

### 方式 1：GitHub 网页直接编辑（最轻，任何设备都行，连 iPad 都可以）⭐

1. 浏览器打开你的 GitHub 仓库
2. 进入 `src/content/posts/` 文件夹
3. 改文章：点某篇 md → 右上角铅笔图标直接改
4. 新文章：右上角 **Add file → Create new file**，文件名如 `my-new-note.md`，
   从现有文章复制头部信息区改一改，写正文
5. 拉到底部点 **Commit changes**

如果配好了自动部署（见部署指南第 4 步），**保存后几分钟网站就自动更新了**——
全程不需要装任何软件，这是"在另一台电脑管理博客"最省事的答案。

### 方式 2：另一台电脑克隆下来写（体验最好，有本地预览）

在那台电脑上做一次性的准备：

```bash
# 1. 安装 Node.js 20+（nodejs.org 下载）和 Git
# 2. 克隆仓库
git clone https://github.com/你的用户名/仓库名.git
cd 仓库名

# 3. 安装依赖并启动本地预览
npm install
npm run dev        # 打开 http://localhost:3000 边写边看
```

以后每次写作：

```bash
git pull           # 开始写之前：先拉取最新内容，避免和网页编辑的冲突
# ……在 src/content/posts/ 里写/改文章……
git add .
git commit -m "新增：xxx 学习笔记"
git push           # 推送后自动部署，网站更新
```

### 方式 3：本机（你现在这台）继续写

流程完全一样，只是别忘了：**开始写之前先 `git pull`**，
因为另一台电脑（或 GitHub 网页）上的修改要先拉回本地，否则 push 时会被拒绝。

## Git 常用命令速查（就这几句够用）

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `git pull` | 把 GitHub 上的最新内容拉到本机 | **每次开始写作前** |
| `git status` | 看看改了哪些文件 | 提交前检查 |
| `git add .` | 把所有改动装进"待提交包" | 写完文章后 |
| `git commit -m "说明"` | 给这次改动拍个快照并命名 | add 之后 |
| `git push` | 把快照上传到 GitHub | commit 之后 |
| `git log --oneline` | 查看历史快照 | 想看看以前改了啥 |

## 冲突了怎么办（很少见）

如果同一篇文章在两边都改了，push 时 Git 会提示冲突。
小白最简单的处理：先把冲突的 md 文件复制一份备份，然后

```bash
git checkout -- 冲突的文件名
git pull
```

再把备份里自己写的内容手动合并回去。愿意学原理的话搜「git 冲突解决」。

## ⏰ 一个提醒

`node_modules/`（依赖）和 `dist/`（构建产物）**不需要也不会**同步到 GitHub——
它们已经在 `.gitignore` 里被排除了。每台电脑克隆后自己 `npm install` 一次即可。
